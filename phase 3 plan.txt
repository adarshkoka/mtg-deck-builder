To implement a Graph-Based Synergy Recommendation System using Keyword Extraction for your Magic: The Gathering Commander deckbuilding application, focusing on the two precon decks, you need a process that extracts meaningful keywords from card text and types, constructs a synergy graph, and recommends cards that synergize with the chosen Commander and chain to secondary synergies. Below, I'll detail how to implement this, tailored to Commander format rules (e.g., color identity, singleton) and leveraging card text and type data. The goal is to recommend cards from both precon decks that work well with the Commander and with each other.
Overview of the Approach
Objective: Build a system that:
Extracts keywords from card text (abilities, triggers, mechanics) and types (e.g., Creature, Enchantment, Artifact).
Creates a graph where cards are nodes, and edges represent synergies based on shared or complementary keywords.
Recommends cards from both precon decks that synergize directly with the Commander (Level 1) and with those synergistic cards (Level 2).
Ensures recommendations are legal in Commander (color identity, no duplicates).
Why Graph-Based with Keyword Extraction?
Graphs naturally model relationships (synergies) and allow chaining (Level 2 synergies).
Keyword extraction captures MTG-specific mechanics (e.g., "Elf," "sacrifice," "whenever") without needing complex NLP.
Feasible for small datasets (~100-200 cards in two precons) and scalable.
Key Assumptions:
You have card data (name, text, mana cost, types, subtypes, deck origin) in a structured format (e.g., JSON).
Cards are from two or more precon Commander decks (e.g., Deck A, Deck B, Deck C, etc.)
Recommendations prioritize synergy strength and cross-deck mixing.

Keyword Extraction:
Sources: Extract from text, types, and subtypes.
Categories of Keywords:
Tribal (Subtypes): Creature subtypes like "Elf," "Zombie," "Goblin," "Human." These are critical for Commander tribal decks (e.g., Lathril, Blade of the Elves synergizes with Elves).
Mechanics: Common MTG mechanics like "token," "counter" (+1/+1 or loyalty), "sacrifice," "exile," "mill," "scry," "draw," "discard," "life gain," "life loss," "damage," "enchant," "equip."
Triggers: Patterns like "Whenever [event], [effect]" (e.g., "Whenever you cast a spell," "Whenever a creature dies").
Enablers: Actions like "Create a [type] token," "Put a +1/+1 counter on," "Deal X damage."
Keywords (Abilities): Static abilities like "Flying," "Trample," "Lifelink," "Haste" (often in text or parsed as keywords in modern data).
Types: Card types like "Creature," "Artifact," "Enchantment," "Instant," which may indicate synergy (e.g., an Enchantment-matter Commander like Sythis).
Extraction Method:
Subtypes/Types: Directly use the subtypes and types fields (e.g., "Elf," "Creature").
Text Parsing: Use regex or string matching to identify mechanics, triggers, and enablers. Example in Python:
import re

def extract_keywords(card):
    text = card["text"].lower()
    subtypes = card["subtypes"]
    types = card["types"]

    # Tribes (from subtypes)
    tribes = set(subtypes)  # e.g., {"Elf", "Druid"}

    # Mechanics
    mechanics = set()
    if "token" in text: mechanics.add("tokens")
    if "counter" in text: mechanics.add("counters")
    if "sacrifice" in text: mechanics.add("sacrifice")
    # Add more: mill, scry, draw, etc.

    # Triggers (simple regex for "Whenever")
    triggers = set()
    if re.search(r"whenever\s+([^\.,]+)", text):
        triggers.add(re.search(r"whenever\s+([^\.,]+)", text).group(1).strip())

    # Enablers (specific actions)
    enablers = set()
    if "create a" in text: enablers.add("create_token")
    if "put a +1/+1 counter" in text: enablers.add("add_counter")

    # Keywords (from text or metadata)
    keywords = set()
    for kw in ["flying", "trample", "lifelink", "haste"]:
        if kw in text: keywords.add(kw)

    return {
        "tribes": tribes,
        "mechanics": mechanics,
        "triggers": triggers,
        "enablers": enablers,
        "keywords": keywords,
        "types": set(types)
    }

# Apply to all cards
card_data = [...]  # Your precon card lists
for card in card_data:
    card["features"] = extract_keywords(card)

2. Build the Synergy Graph
Create a graph where nodes are cards, and edges represent synergies based on keyword matches or complementary effects.
Graph Setup:
Use a graph library (e.g., NetworkX in Python, or a simple adjacency list in JavaScript).
Nodes: All cards from both precon decks (~100-200 nodes).
Edges: Weighted connections based on synergy strength.
Edge Creation (Synergy Scoring):
Rules for Synergy: Assign weights based on keyword matches or complementary mechanics:
Tribal Match: +5 if cards share a subtype (e.g., both are Elves).
Mechanic Complementarity: +4 for enabler-trigger pairs (e.g., one card creates tokens, another triggers on tokens entering/dying).
Example: If Card A has enabler "create_token" and Card B has trigger "whenever a creature enters," add +4.
Shared Mechanic: +3 if both cards use the same mechanic (e.g., both involve "counters").
Shared Keywords: +2 if both have the same ability (e.g., "Flying").
Type Synergy: +2 if both share a type and the Commander cares about it (e.g., Enchantments for Sythis).
Cross-Deck Bonus: +2 if cards are from different decks (to encourage mixing).
Color Identity Penalty: -10 if the card’s color identity violates the Commander’s (e.g., a red card in a mono-green Commander’s deck). Use mana symbols and text to check.
Threshold: Only create an edge if the score is ≥3 (adjust based on testing to avoid weak links).
Implementation Example (Python with NetworkX):
import networkx as nx

G = nx.Graph()

# Add nodes
for card in card_data:
    G.add_node(card["name"], features=card["features"], colors=card["colors"], origin=card["origin_deck"])

# Add edges
for i, card1 in enumerate(card_data):
    for card2 in card_data[i+1:]:
        score = 0
        # Tribal match
        if card1["features"]["tribes"] & card2["features"]["tribes"]:
            score += 5
        # Mechanic complementarity (example: tokens)
        if "create_token" in card1["features"]["enablers"] and any("creature enters" in t for t in card2["features"]["triggers"]):
            score += 4
        # Shared mechanics
        if card1["features"]["mechanics"] & card2["features"]["mechanics"]:
            score += 3
        # Shared keywords
        if card1["features"]["keywords"] & card2["features"]["keywords"]:
            score += 2
        # Type synergy
        if card1["features"]["types"] & card2["features"]["types"]:
            score += 2
        # Cross-deck bonus
        if card1["origin_deck"] != card2["origin_deck"]:
            score += 2
        # Color identity check (skip if invalid for either card's Commander context)
        if score >= 3:
            G.add_edge(card1["name"], card2["name"], weight=score)
Optimization: For two precons (~200 cards), computing all pairs (~20k comparisons) is fast (<1s on modern hardware). Precompute and cache the graph if decks are static.

    commander_colors = set(commander["colors"])  # E.g., ["G", "B"]
    card_colors = set(card["colors"])
    return card_colors.issubset(commander_colors)

Singleton Rule: Exclude non-land duplicates from recommendations unless basic lands.

Tribal Decks: Many precons are tribal (e.g., Elves, Zombies); prioritize tribal keywords heavily (+5 score) for Commanders like Lathril.
Dynamic Updates: If the user adds non-precon cards, update the graph or flag them for manual review.
